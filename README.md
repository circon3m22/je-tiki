# Je Tiki

Интернет-магазин украшений и небольших предметов из натурального дерева и серебра. Проект собран на Next.js 16, React 19, TypeScript и Tailwind CSS. Каталог может работать на локальных данных, а реальные заказы создаются только при настроенных Supabase и ЮKassa.

## Требования

- Node.js 22.13 или новее;
- pnpm 11.9 или совместимая версия;
- для приёма заказов — проекты Supabase и ЮKassa;
- для уведомлений — Resend и/или Telegram Bot API.

## Локальный запуск

```bash
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

Откройте `http://localhost:3000`. Без переменных Supabase сайт использует типизированный локальный каталог из `lib/catalog/products.ts`. Корзина и недавно просмотренные изделия сохраняются в `localStorage` браузера.

## Проверки и production build

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm build
pnpm start
```

Перед публикацией все четыре проверки должны завершаться без ошибок. `pnpm start` запускается только после успешного `pnpm build`.

## Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните нужные значения.

| Переменная                                                 | Назначение                                                        |
| ---------------------------------------------------------- | ----------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`                                     | Канонический публичный URL сайта                                  |
| `NEXT_PUBLIC_SUPABASE_URL`                                 | URL проекта Supabase                                              |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`                     | Публичный ключ чтения каталога                                    |
| `SUPABASE_SECRET_KEY`                                      | Секретный серверный ключ для заказов; не добавлять `NEXT_PUBLIC_` |
| `YOOKASSA_SHOP_ID`                                         | Идентификатор магазина ЮKassa                                     |
| `YOOKASSA_SECRET_KEY`                                      | Секрет ЮKassa, только сервер                                      |
| `YOOKASSA_RETURN_URL`                                      | URL возврата, например `https://site.ru/order/success`            |
| `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`                     | Резерв для будущего подключения расчёта СДЭК                      |
| `RESEND_API_KEY`, `EMAIL_FROM`, `ORDER_NOTIFICATION_EMAIL` | Email-уведомления и форма контактов                               |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`                   | Уведомление владельца в Telegram                                  |

Legacy-переменные `NEXT_PUBLIC_SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` поддерживаются для миграции существующего проекта, но для нового проекта используйте publishable/secret keys.

## Настройка Supabase

1. Создайте новый проект в Supabase.
2. Возьмите Project URL, publishable key и secret key в настройках API.
3. Добавьте их в `.env.local`.
4. Откройте SQL Editor и выполните миграцию `supabase/migrations/20260727143824_initial_commerce_schema.sql`.
5. Выполните `supabase/seed.sql` для загрузки 15 изделий и их изображений.
6. Убедитесь, что Data API предоставляет доступ к `public.products` и `public.product_images`. Миграция уже выдаёт только `SELECT` ролям `anon` и `authenticated` и включает RLS.

Миграция создаёт таблицы `products`, `product_images`, `orders`, `order_items`, индексы, триггеры и атомарную RPC-функцию `create_checkout_order`. Публичное изменение каталога и чтение заказов запрещены. Заказы создаются только серверным клиентом с секретным ключом.

Если используете Supabase CLI, сначала посмотрите актуальные команды через `supabase --help`, затем примените миграцию стандартным workflow вашего проекта. Не храните секретный ключ в браузере или Git.

## Изображения и Supabase Storage

Первая версия использует локальные WebP в `public/images`. Авторы и исходные страницы перечислены в `IMAGE_CREDITS.md`.

Для переноса оригинальной съёмки в Supabase Storage:

1. создайте публичный bucket для каталога;
2. загрузите оптимизированные WebP или AVIF;
3. добавьте точные alt-тексты;
4. замените `image_url` в `product_images`;
5. добавьте hostname Storage в разрешённые изображения `next.config.ts` через `NEXT_PUBLIC_SUPABASE_URL`;
6. проверьте карточки и метаданные продукта.

Для простой замены без Storage сохраните новое изображение по существующему пути. Вёрстка и данные менять не потребуется. Не удаляйте `IMAGE_CREDITS.md`, пока на сайте остаются стоковые материалы.

## Изменение товаров

- Локальный источник: `lib/catalog/products.ts`.
- Наборы изображений: `lib/catalog/images.ts`.
- Категории: `lib/catalog/categories.ts`.
- Supabase: таблицы `products` и `product_images`.

Цены хранятся целыми рублями, вес — в граммах. `is_available=true` вместе с `is_made_to_order=true` позволяет принимать заказ при нулевом складском остатке без списания отрицательного количества. Для обычной позиции сервер блокирует заказ, если запрошенное количество превышает остаток.

## Контакты, соцсети и реквизиты

Центральная конфигурация находится в `lib/config/site.ts`. Заполните:

- телефон, email и режим работы;
- Instagram, Telegram и витрину Wildberries;
- полное наименование продавца, ИНН, ОГРН/ОГРНИП и адрес;
- настройки доставки, бесплатной доставки и SEO.

Пустые контакты и ссылки автоматически скрываются. До публикации юридических страниц обязательно внесите реальные реквизиты продавца; проект намеренно не содержит выдуманных данных.

## Подключение ЮKassa

1. Получите `shopId` и секретный ключ в кабинете ЮKassa.
2. Заполните `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` и `YOOKASSA_RETURN_URL`.
3. Укажите HTTPS return URL вида `https://site.ru/order/success`.
4. Разверните сайт и выполните заказ с минимальной разрешённой суммой в предусмотренном ЮKassa режиме проверки.

`POST /api/checkout` получает только ID и количество, повторно читает цену и остаток из Supabase, атомарно резервирует обычный складской товар, создаёт заказ, затем создаёт платёж с UUID-ключом идемпотентности. Без Supabase и ЮKassa endpoint возвращает понятную ошибку и не создаёт фиктивный заказ.

## Webhook ЮKassa

В кабинете ЮKassa подпишите URL:

```text
https://site.ru/api/payments/yookassa/webhook
```

Включите события `payment.succeeded` и `payment.canceled`. Уведомления ЮKassa не имеют общего shared-secret: обработчик повторно получает платёж из API ЮKassa, сверяет ID заказа, номер, валюту и сумму и только после этого меняет статус на `paid`. Возврат пользователя на страницу успеха сам по себе не подтверждает оплату.

Статус доступен через `GET /api/orders/{orderNumber}/status` и проверяется сервером у платёжного провайдера.

## Email и Telegram

Модуль `lib/notifications/order-notifications.ts` вызывается после подтверждённой оплаты. Он умеет:

- отправить покупателю подтверждение через Resend;
- отправить владельцу состав заказа через Resend;
- отправить владельцу сообщение через Telegram Bot API.

Ошибки уведомлений изолированы и не откатывают оплату. Для защиты от повторной отправки используется `notifications_sent_at`. Форма контактов использует те же Resend-переменные.

## Подключение СДЭК

Сейчас фиксированные тарифы находятся в `lib/checkout/delivery.ts`. Чтобы подключить СДЭК позднее:

1. получите API credentials и заполните CDEK-переменные;
2. создайте серверный адаптер расчёта тарифа и выбора ПВЗ;
3. замените реализацию `calculateDeliveryPrice`, сохранив тип `DeliveryMethod` и контракт checkout;
4. не вызывайте CDEK с секретами из Client Component;
5. повторно проверяйте рассчитанный тариф на сервере перед созданием заказа.

## Проверка заказа

Для сквозной проверки нужен отдельный проект Supabase и предусмотренный ЮKassa режим проверки:

1. примените migration и seed;
2. настройте URL, ключи и webhook;
3. добавьте товар в корзину, перезагрузите страницу и убедитесь, что количество восстановилось;
4. заполните доставку и контакты;
5. проверьте ошибку при количестве выше остатка;
6. перейдите на ЮKassa и завершите разрешённую проверочную оплату;
7. убедитесь, что `paid` появился только после серверной проверки или webhook;
8. проверьте строки `order_items`, снимок цены и уведомления.

Не используйте реальные платёжные данные вне безопасного режима, предоставленного платёжным оператором.

## Развёртывание на Vercel

1. импортируйте репозиторий в Vercel;
2. выберите preset Next.js и pnpm;
3. добавьте переменные окружения для Production и Preview;
4. установите `NEXT_PUBLIC_SITE_URL` в реальный HTTPS-домен;
5. выполните deployment;
6. обновите `YOOKASSA_RETURN_URL` и webhook на production URL;
7. проверьте `/robots.txt`, `/sitemap.xml`, Open Graph и основные маршруты.

Build command: `pnpm build`. Output определяется Next.js автоматически.

## Структура

```text
app/                    страницы, SEO-файлы и Route Handlers
components/             интерфейс, каталог, корзина и формы
lib/catalog/            данные и repository/service слой каталога
lib/cart/               localStorage-корзина Zustand
lib/checkout/           серверный расчёт и создание заказа
lib/payments/           адаптер ЮKassa
lib/notifications/      email и Telegram
lib/supabase/           server-only клиент
lib/validation/         Zod-схемы
public/images/          локальные оптимизированные изображения
supabase/migrations/    схема, RLS и RPC
supabase/seed.sql       15 товаров и 75 изображений
```

## Чек-лист перед публикацией

- заполнены контакты и реальные реквизиты;
- заменены или проверены фотографии и alt-тексты;
- проверены цены, остатки, made-to-order и ссылки Wildberries;
- применены migration и seed;
- секреты отсутствуют в `NEXT_PUBLIC_*` и клиентском коде;
- успешно проходят format, lint, typecheck и build;
- проверены главная, каталог, категории, товар, корзина, checkout, 404, robots и sitemap;
- проверены клавиатурная навигация, фокус, экран 320 px и reduced motion;
- webhook подтверждает оплату, повторный submit не создаёт дубль;
- уведомления работают либо корректно отключены;
- на production нет пустых ссылок и незаполненных реквизитов.
