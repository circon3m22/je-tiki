`cdtsugmnufqldbmeemwn` **11 ноября 2026, 20:35:57 по Владивостоку**
(`2026-11-11T10:35:57.118297Z`). Файлы Storage скачаны отдельно после снимка.

| Записи изображений | 135 |

Все поля сохранены: UUID, цены, остатки, статусы, описания, характеристики,
SEO, порядок фотографий и связи. `catalog.json` содержит данные и метаданные
Storage; `schema.json` — описание текущих столбцов и ограничений.
`media/product-media/` содержит оригинальные байты файлов с исходными путями;
`media/external/` — копии изображений по внешним ссылкам. `assets.json`
сопоставляет URL с локальными файлами. `manifest.json` содержит точные
количества, размеры и SHA-256 всех остальных файлов этой копии.

Это копия каталога, а не полный дамп проекта Supabase. Схема и политики
приложения восстанавливаются миграциями из `supabase/migrations/`.
Учётные записи, пароли, ключи API, заказы и корзины в копию не входят.

## Проверка

Из корня репозитория, Python 3.9 или новее:

```sh
python3 backups/catalog/2026-11-11T103557Z/verify.py
```

Проверяются состав файлов, SHA-256, размеры, количества, уникальность ключей,
связи товаров и наличие всех изображений. При скачивании также проверены
размеры Storage и MD5 из ETag, когда он доступен.

## Восстановление данных

1. Создайте отдельный проект Supabase и примените миграции репозитория на
   коммите, указанном в `manifest.json` (`source_repository_commit`).
2. Миграции добавляют начальный каталог. **Только в новом проекте без рабочих
   данных** очистите его запросом ниже. Проверка блокирует очистку при наличии
   корзин и позиций заказов; не используйте этот запрос для рабочего магазина.

```sql
BEGIN;
DO $$ BEGIN
  IF EXISTS (SELECT 1 FROM public.cart_items)
     OR EXISTS (SELECT 1 FROM public.order_items) THEN
    RAISE EXCEPTION 'Target has shopping activity; use a new project';
  END IF;
END $$;
DELETE FROM public.product_images;
DELETE FROM public.collection_products;
DELETE FROM public.products;
DELETE FROM public.collections;
DELETE FROM public.categories;
COMMIT;
```

3. Выполните `restore.sql` в SQL Editor нового проекта либо через `psql`:

```sh
psql "$TARGET_DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f backups/catalog/2026-11-11T103557Z/restore.sql
```

SQL откажется работать с непустым каталогом, восстановит исходные UUID и
связи в одной транзакции и сверит все поля с данными снимка перед `COMMIT`.
Для схемы требуется версия миграций из этого репозитория.

## Восстановление изображений

Сначала можно выполнить безопасную локальную проверку:

```sh
python3 backups/catalog/2026-11-11T103557Z/restore_media.py
```

Для загрузки задайте `SUPABASE_URL` **нового** проекта и его
`SUPABASE_SERVICE_ROLE_KEY` в окружении терминала, затем:

```sh
python3 backups/catalog/2026-11-11T103557Z/restore_media.py --execute
```

Скрипт создаст отсутствующий bucket и загрузит 139 файлов через Storage API
с исходными путями. По умолчанию существующие объекты не перезаписываются;
для осознанного повторного запуска предусмотрен `--overwrite`.
В `storage.objects` напрямую ничего вставлять не нужно.
Секретный ключ используется только из окружения и не сохраняется в файлы.

Ссылки в данных сохранены без изменений. Внешние изображения уже находятся
в `public/images/je-tiki/` репозитория; их байты дополнительно сохранены здесь.
Если меняете домен сайта или проект Supabase, замените соответствующие
абсолютные URL в восстановленных данных и настройте переменные приложения.
`storage_path` менять не нужно.

Проверено восстановление всех пяти таблиц на отдельном PostgreSQL 17
с текущими типами, ограничениями и триггером связи коллекций; все строки
совпали со снимком. Рабочая база при создании этой копии не изменялась.
